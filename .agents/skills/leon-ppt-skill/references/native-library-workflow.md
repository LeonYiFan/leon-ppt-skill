# 原生页型和组件

原生选版使用单独保管的本地素材库。将已配置的库路径传给 `build_report.py --native-library`。没有该库时使用随附的空白模板、常规页型和可编辑证据卡。先用 GUT 文献答辩（`gut`）与指南项目答辩（`guide`）建立整稿风格。使用 KW16 合集（`kw16`）与第九套（`kw16-9`）补充细部结构。源页实际页码从 1 起。

## 先看真实参考页

根据本次的内容证据决定版式。先找能承担相同信息关系的两份主参考页面，浏览预览，确认主次、形状层级和有效绘图区。比如精简两组图形可先看 GUT 29，原图并排与中央指标看 GUT 41，分轨技术路线看指南 13，风险应对看指南 30。日程或通用并列关系也可查 KW16。选择后记下来源、页码、使用的槽位和未使用的内容。原材料中带回隐私和过往结论的区域留空，当前稿显示本次素材和数据。

```powershell
python -X utf8 scripts/make_native_catalog.py search --query 分轨 --limit 6
python -X utf8 scripts/make_native_catalog.py search --source gut --page 29 --slots --assets
python -X utf8 scripts/make_native_catalog.py suggest --intent method_evidence --figures 2
python -X utf8 scripts/make_native_catalog.py suggest --figures 3 --min-width 5.5 --text-slots 4
```

上面的命令从技能目录运行。程序返回源 PPTX、预览路径、图层和形状真实 ID、位置以及关联资源。浏览和查找只需技能目录中的素材库，原始位置迁移后仍可选版。所有原始素材均保存在库里，包括母版、布局、图表和相关工作簿、嵌入图片、字体与分组信息。库内的原稿副本和预览仅供本地选版。

`suggest` 对 676 页按图框净尺寸、图数、原生文字量和表格查询。 `recipe` 带已配置的页型或组件 ID 与必需字段。 `inspect` 给可人工核对的候选图框与实际页码，图框可能是装饰或原来图表的位置。先看缩略图与真实槽位，再决定复用。KW16 两套的完全重复预览在候选阶段合并展示。

## 按容量自动选页

让每页的 `type` 描述可用的常规页型，再加 `native_auto` 提供优先的原生结构。顶层 `prefer_native: true` 会尝试识别常见证据、三栏、风险或分轨构成，单页可用 `native_auto: false` 保留原型。构建器核对图数、原图比例、显示尺寸、正文行数、源字体宽度和字段完整度，优先采用合适的 GUT 或指南。KW16 按需作为局部组件。每次选择在本地 `delivery.json` 留下源页、槽位、图幅和候选判断。需复现已选版式时，可写 `native_profile` 为查询得到的确切 ID，仍经过适配检查。

- `figure_evidence` 用在 `bullets` 页，每张图给 `path`、`caption`，零到两条 `bullets`。GUT 已配置一、二、三图的原生页。文字按实测宽度确定字号和行高，卡片从末行下方起排。单张横幅图用紧凑卡片，两个适合上下读的宽幅面板会与并排候选一起比较。图卡边线和标题条对齐，原图按比例放入。单张图可用 `figure_legend` 保留一行可核对的编辑式图例。四图或候选不足时可用实测过容量的常规图位。图可以声明 `min_width_cm` 和 `min_height_cm`。图幅仍不够则拆成独占图页。
- `parallel_cards` 用在 `triple` 页，给一条总要点和三项 `cards`，每项 `title` 加一到两行 `note`。
- `risk_response` 用在 `bullets` 页，`component.intent` 同为 `risk_response`。三项 `items` 分别填 `title`、`tag`（左栏小标题与说明），以及两行 `body`（右栏小标题与说明）。用 `component.headers` 改成适合本页的两个栏标题，例如「已获得的证据」「尚待回答的问题」。经核对的指南双栏安全区保持原卡片、原字号和统一边距。

上述内容页都填写 `title`、`summary`、`source`、`notes`。更多已绑定源页槽位的结构见 [深度蒸馏页型](distilled-layouts.md)。字段超出容量时按报错换版或拆页，保留完整内容。

## 使用整页原生版式

在 plan 中指定 `type: "native"`，用 `native` 中的来源、页码和实际槽位构建。标题、红字及讲稿根据当前内容填写。内容页保留结论式标题、要点和灰底总结条，图源放演讲者备注，封面和章节页按原来规则。组内子对象可用实际子对象 ID 填充。

```json
{"type":"native","native":{"source":"gut","page":1,"artwork":["4"],
  "text":{"5":"文献汇报","10":"汇报题名"}},"notes":"填写当页讲稿"}
```

以上仅示意字段结构。始终先查当前页的槽位，按实际 ID 填。整页取源页的编辑对象、图层顺序和模板背景，填充项如下。

| 字段 | 用法 |
| --- | --- |
| `text` | 以文本或形状的 ID 填新文案，可用换行和 `**关键词**`。默认保留源版的文字层级 |
| `tables` | 以原生表格的 ID 填入行列相同的新表。原有表格数据清空 |
| `images` | 以图片、图表或媒体占位 ID 放本次任务的新图。按比例放入原图槽位 |
| `artwork` | 复用原稿装饰图的实际 ID，只用于本地清单内已经查验的无身份装饰 |
| `omit` | 需要删除的多余对象或组的 ID。先删腾不出内容的装饰区域，避免留下无意义的空卡 |

源文本按本次材料替换。源图表、SmartArt、附加文档、音视频、动画与其他复杂对象保留在本地原稿。输出时按当前任务重建，或在原槽位放置当前证据。图源在整页的外层给 `source`，构建时写入演讲者备注。旧的 `source_box` 是图源页脚坐标，新稿可省。

正式汇报的手工原生页用外层 `native_audit` 绑定实际源 ID。正文页标出 `title` 和 `summary`。旧计划以 `source` 角色绑定的正文页脚会移入备注。卡片以内的文字可声明归属，渲染时检查留白。下面的 ID 仅用于演示字段。

```json
{
  "native_audit": {
    "roles": {"2": "title", "7": "body", "76": "summary"},
    "containers": [{"shape_id": "7", "container_id": "191", "inset_pt": [6, 4, 6, 4]}]
  }
}
```

两份主参考的匿名浅蓝背景、标题线等已核对的版式元素优先沿用。带徽标、姓名、单位、联系方式或历史实验内容的图片留在私有素材库。此次审核过的匿名蓝带、灰总结条、箭头和通用图标可按其真实图片 ID 选用。

## 使用某个原生组件

在普通页或原生页的 `native_components` 中列出一项或多项。每项通过 `include` 给出来自同一源页的顶层对象或组合 ID，按需给 `text`、`tables`、`images`、`artwork`，格式同上。省略 `box` 时保持源页坐标。填写 `box: [x, y, w, h]`（cm）时在指定区域内整体等比放置。填充组内文字使用子对象 ID。组件不会带入来源页的背景，选择时保留相互配合的标题带、卡片、连线和底板。

组件内部同样可用 `audit.roles` 和 `audit.containers` 标注源 ID 及卡片关系。构建器把源 ID 转成成品 ID，最终验收读取成品 ID。

将渲染成品与选用的源页预览并看。优先检查图层里真正决定风格的标题位置、栏宽、色块和图间距。科学图轴标过小就在原有版式内放大绘图区或另页。文本、表格及备注沿用已有匿名检查。
